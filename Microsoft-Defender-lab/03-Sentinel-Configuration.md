# Learning Path 6 — Lab 1, Exercise 1  
## Configure Microsoft Sentinel Environment

## Purpose

Configure Microsoft Sentinel features that support SOC operations, threat hunting, compliance, and cost management:

- Create a **watchlist** of high-value hosts.
- Create a **threat intelligence indicator**.
- Configure **log retention** for a security-event table.

# Task 1 — Create a Watchlist

## Purpose

A **watchlist** is a custom list of values used to enrich KQL queries. In this lab, the list identifies high-value hosts that deserve additional analyst attention.

## Create source CSV

1. Sign in to `WIN1` as `Admin`.
2. Open **Notepad**.
3. Create this CSV content:

```csv
Hostname
Host1
Host2
Host3
Host4
Host5
```

4. Save it as:

```text
Documents\HighValue.csv
```

5. When saving, select:

```text
Save as type: All files
```

## Create the Sentinel watchlist

1. Open:

```text
https://security.microsoft.com
```

2. Navigate to:

```text
Microsoft Sentinel > Configuration > Watchlist
```

3. Select:

```text
+ New
```

4. Enter:

| Field | Value |
|---|---|
| Name | `HighValueHosts` |
| Description | `High Value Hosts` |
| Watchlist alias | `HighValueHosts` |

> In a shared environment, append initials to the name and alias to avoid conflicts.

5. Select:

```text
Next: Source
```

6. Upload:

```text
Documents\HighValue.csv
```

7. Set the **SearchKey** to:

```text
Hostname
```

8. Select:

```text
Next: Review and Create > Create
```

9. Refresh the Watchlist page and confirm the watchlist appears.

## Query the Watchlist

```kql
_GetWatchlist('HighValueHosts')
```

Reference the host value using:

```kql
Hostname
```

### Example use in hunting

```kql
SecurityEvent_CL
| where Computer in (_GetWatchlist('HighValueHosts') | project Hostname)
```

> This returns security events generated by devices listed as high-value hosts.

## Key Notes

- Watchlists can take up to **10 minutes** to become available.
- A watchlist is useful for high-value assets, privileged accounts, known bad IPs, VIP users, service accounts, or approved administrative tools.
- The **SearchKey** is the primary field used when matching watchlist entries in KQL.

# Task 2 — Create a Threat Indicator

## Purpose

A **threat intelligence indicator** is an observable associated with suspicious or malicious activity. Examples include domains, IP addresses, URLs, file hashes, and email addresses.

## Create the Indicator

1. Navigate to:

```text
Microsoft Sentinel > Threat management > Threat intelligence
```

2. Select:

```text
Open Intel management
```

3. Select:

```text
+ New
```

4. Configure:

| Field | Value |
|---|---|
| TI Object | `Indicator` |
| Observable type | `Domain name` |
| Domain | `contoso.com` |
| Name | `contoso.com` |
| Indicator type | `malicious-activity` |
| Valid from | Today’s date |
| Description | `This domain is known to be malicious.` |

> In a shared environment, add initials or a unique identifier to the domain value if the domain already exists.

5. Select:

```text
Add
```

## Query Threat Indicators

Navigate to:

```text
Investigation & response > Hunting > Advanced hunting
```

View all available indicators:

```kql
ThreatIntelIndicators
```

View only observable values:

```kql
ThreatIntelIndicators
| project ObservableValue
```

## Key Notes

- Threat indicators can take up to **five minutes** to appear.
- `ObservableValue` contains the actual observable, such as a domain, IP address, URL, or hash.
- Threat intelligence supports hunting, detections, enrichment, and incident investigations.

# Task 3 — Configure Log Retention

## Purpose

Retention settings determine how long log data remains available for analytics, investigation, compliance, and threat hunting. Retention must balance security requirements against storage cost.

## Configure `SecurityEvent_CL`

1. Navigate to:

```text
Microsoft Sentinel > Configuration > Tables
```

2. Search for:

```text
SecurityEvent
```

3. Select:

```text
SecurityEvent_CL
```

> Ensure the selected table is the custom training-lab table, not another `SecurityEvent` variation.

4. Open:

```text
Data retention settings
```

5. Set:

```text
Analytics retention: 90 days
```

6. Confirm:

```text
Total retention period: Same as Analytics retention (90 days)
```

7. Select:

```text
Save
```

8. Select the **Data lake tier** option and verify:

```text
Retention: 180 days
```

## Retention Tiers

| Tier | Lab setting | Main purpose |
|---|---:|---|
| Analytics tier | 90 days | Fast investigation, hunting, detections, and analytics queries |
| Data lake tier | 180 days | Longer-term storage for compliance, historical analysis, and lower-cost retention |

## Key Notes

- Shorter analytics retention can reduce cost but limits fast access to historical data.
- Longer retention improves investigation and compliance capability but can increase storage costs.
- Retention requirements should consider regulations, incident-investigation needs, organizational risk, and budget.

# Key Takeaways

| Feature | Purpose |
|---|---|
| Watchlist | Custom lookup list for KQL enrichment and prioritized monitoring |
| `_GetWatchlist()` | KQL function used to access a Sentinel watchlist |
| SearchKey | Watchlist column used for matching values in queries |
| Threat indicator | Observable linked to potential malicious activity |
| `ThreatIntelIndicators` | Table containing threat-intelligence indicators |
| `ObservableValue` | The domain, IP, URL, hash, or other observable value |
| Analytics retention | High-performance period for active SOC investigation and hunting |
| Data lake tier | Longer-term retained data for historical access and compliance |
