Study companion • ISO and control effectiveness

From an ISO requirement
to evidence that a control works

One connected example: treating the risk of confidential client information leaving through unauthorised email sharing.

Terminology correction: the control reference is Annex A of ISO/IEC 27001, not “Annex 2.” ISO/IEC 27002 is a separate standard providing control guidance. This page uses the 2022 editions.
27001 requirement → Annex A reference control → 27002 guidance → local implementation → assessment evidence

All standard-related explanations below are educational paraphrases, not verbatim extracts. The fictional implementation and test plan are not ISO-prescribed configurations, actual test results or evidence of conformity.

1 · Management-system requirement
ISO/IEC 27001:2022
6.1.3(b)–(d)

Information security risk treatment

Determine the controls needed for the chosen risk treatment, compare them against Annex A to check for omissions, and document the necessary controls and applicability decisions in the Statement of Applicability.

The SoA addresses inclusion rationale, implementation status and justification for excluding Annex A controls. Necessary controls can also come from outside Annex A.

Question answered: How do we determine and account for the controls we need?

Selected aspects of clause 6.1.3 only—not its complete set of requirements. Sources: 3 and 4.

2 · Reference control
ISO/IEC 27001:2022
Annex A · A.8.12

Data leakage prevention

Apply measures against leakage in the systems, networks and devices handling sensitive information.

This is a reference control to consider in the risk-treatment process. Its presence in Annex A does not automatically make it necessary for every organisation, nor does it specify a particular DLP product.

Question answered: Which protective capability is relevant to the risk?

Control description paraphrased. Sources: 3 and 5.

3 · Implementation guidance
ISO/IEC 27002:2022
Control 8.12

Turning the control into practice

  • Identify sensitive information and classify it appropriately.
  • Consider leakage paths such as email, file transfer and portable devices.
  • Monitor relevant channels and select measures that prevent inappropriate disclosure.
  • Consider tools to identify, detect and restrict risky data movement.

Selected guidance themes, paraphrased—not the complete guidance. Source: 5.

How these three layers connect

27001 establishes the management-system obligation. Annex A supplies a reference set for comparison. 27002 explains control implementation considerations. The organisation then designs its own appropriate implementation and evaluates the resulting evidence.

Annex A is normative in its use with the risk-treatment process, but it is not a blanket instruction to implement every reference control. Applicability and exclusion decisions need justification. Sources: 3 and 4.

One risk, connected from decision to evidence

RiskAn employee may send confidential client information to an unauthorised external recipient, causing disclosure and client or contractual harm.Documented business context, relevant data flows and assessment assumptions.
Treatment decisionReduce unauthorised external disclosure while preserving an approved collaboration route.A treatment plan with owners, actions, dependencies and appropriate approvals.
ApplicabilityData leakage prevention is necessary for this assessed exposure; map local control DP-EMAIL-01 to A.8.12.SoA entry: inclusion rationale, implementation status and supporting references.

The 100-user pilot and the evidence suggestions are a teaching design. Email coverage alone does not establish coverage of every channel.

Sample effectiveness checks

These proposed checks connect the lesson to a practical assessment. No outcomes have been observed.

CheckScenarioExpected outcome / interpretation
Core protectionIn-scope user attempts external transfer of recognised confidential content with enforcement enabled.The configured restriction occurs; verify the actual outcome, not only a rule match.
Legitimate useIn-scope user sends a permitted public document externally.This confidential-content rule does not restrict the activity; other policies may still apply.
Scope boundaryAn excluded test user attempts the same activity.Record that the pilot does not provide coverage for that user. Expected behaviour does not eliminate the exposure.
Detection boundaryConfidential synthetic content lacks the configured detection marker.Determine actual detection behaviour; document any gap against the intended requirement.

Design: would the mechanism address the risk? Implementation: is it configured in the required scope? Operation: does evidence support its functioning under the assessed conditions and period?

These are practical assessment questions, not an ISO-mandated three-part template. A successful point-in-time test does not by itself prove continuous operation.

Check your understanding

Does A.8.12 tell us to buy a particular product?

No. The organisation determines appropriate measures based on its risks and requirements. A product can support implementation; buying one does not prove effectiveness.

Is ISO/IEC 27002 a second annex of ISO/IEC 27001?

No. It is a separate guidance standard. The relevant reference set inside ISO/IEC 27001 is Annex A.

Does an SoA entry prove that a transfer was blocked?

No. The SoA explains applicability and implementation status. A blocking claim needs evidence of the relevant behaviour and outcome.

What should I say in an interview?

“I would connect the risk-treatment requirement in clause 6.1.3 with the relevant Annex A reference control, use ISO 27002 guidance to inform implementation, and then evaluate evidence within a defined scope. Listing a control and proving its effectiveness are different things.”
